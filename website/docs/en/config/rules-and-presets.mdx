# Rules & Presets

Presets provide ready-to-use groups of rules. Add them directly to the flat config array, then use a later [`rules`](/config/rules) entry for project-specific overrides.

The `node.configs.recommended`, `recommended-module`, and `recommended-script` presets correspond to [eslint-plugin-n's `recommended`, `recommended-module`, and `recommended-script`](https://github.com/eslint-community/eslint-plugin-n/tree/v18.3.0/lib/configs). They enable native `node/*` rules and declare Node.js globals:

```ts
import { defineConfig, node } from '@rslint/core';

export default defineConfig([node.configs.recommended]);
```

`recommended` is an array of flat config entries. When selected, it reads the nearest valid `package.json` from the process working directory: `"type": "module"` selects ES modules, otherwise CommonJS. Overrides treat `.mjs` as ES modules and `.cjs` as CommonJS, including dotfiles. Like upstream, this default does not detect each file's nearest package type; use file-scoped `recommended-module` or `recommended-script` entries for packages with different types.

`recommended-module` disables the CommonJS globals (`require`, `module`, `exports`, `__dirname`, and `__filename`) and ignores `modules` in `node/no-unsupported-features/es-syntax`. `recommended-script` uses `sourceType: 'commonjs'`, enables those globals, and keeps the syntax rule's `ignores` empty. Both include the bundled Node.js and ES2021 global sets, following upstream's flat config shape. `sourceType` controls lint scopes and strict-mode behavior; it does not change TypeScript parsing.

The upstream `process-exit-as-throw` rule is not implemented and is omitted, as with unavailable rules in other presets. Set `engines.node` in `package.json` or `settings.node.version` to configure the Node.js version checked by the three `node/no-unsupported-features/*` rules.

## Choosing a TypeScript preset

The `ts.configs.*` presets mirror typescript-eslint's own layering. Pick one baseline:

| Baseline                 | What it covers                                                                        |
| ------------------------ | ------------------------------------------------------------------------------------- |
| `recommended`            | Rules that catch code likely to be buggy, using syntax alone                          |
| `recommendedTypeChecked` | `recommended` plus the rules that read type information                               |
| `strict`                 | `recommended` plus opinionated rules that catch more bugs at the cost of more reports |
| `strictTypeChecked`      | `strict` plus the rules that read type information                                    |

`stylistic` and `stylisticTypeChecked` hold the consistency rules. Layer one after the baseline:

```ts
export default defineConfig([
  js.configs.recommended,
  ts.configs.strictTypeChecked,
  ts.configs.stylisticTypeChecked,
]);
```

Every `ts.configs.*` preset declares the `@typescript-eslint` plugin. Like upstream, presets do not set project discovery options. Enable `parserOptions.projectService: true` explicitly for automatic discovery, or use `parserOptions.project` to select TypeScript projects. Type-aware rules run only for files with a selected project; [gap files](/guide/type-checking#gap-files) retain source-only linting.

To configure a rule manually, see [`rules`](/config/rules). To enable rules outside a preset, see [`plugins`](/config/plugins). The complete [Rules](/rules/) reference documents rule-specific options.
